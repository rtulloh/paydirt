## Description

The owner requests replacing the full-season runner's generated rotating schedule
with actual historical fixtures and parameterizing the selected season, for
example `python3 tests/run_full_season.py 1983`. The current runner hardcodes
1983, 28 teams, 16 generated weeks and the ten-team/nine-game bracket. Its
documentation correctly labels that generated behavior; it does not provide the
new requested historical or cross-year qualification.

Historical fixture/result validation must work with available generated charts
when developer charts are absent. Developer-reference comparison is additional
evidence, never a prerequisite for a historical-results audit. Engine charts
and historical targets are still required; missing inputs must fail explicitly.

## Resolution / verification

- Select actual season fixtures, source game IDs, dates/weeks, home/away teams,
  historical results, conference/division membership and supported source-year
  postseason/rule specification. Preserve provenance and incomplete coverage.
  No silently generated schedule or guessed membership/format fallback.
- Accept the selected year and explicit chart/input locations as needed. Preserve
  a documented no-argument default compatible with the required regression
  invocation. Validate team mappings, duplicate/incomplete fixtures, historical
  results and required rules before games start.
- Run the actual regular-season calendar. Compare simulated scores, wins/ties,
  standings, strengths and uncertainty against historical results without
  asserting exact outcomes or the historical champion are required.
- Derive simulated postseason entrants from simulated standings under declared
  year-appropriate qualification/bracket/byes/reseeding/tiebreak/overtime rules.
  Separately identify any replay of actual historical postseason fixtures. Never
  force historical participants in a counterfactual qualification-probability
  study. Disclose any unsupported tiebreaks or rules rather than certifying them.
- Retain complete game/round/count/scoring receipts, failure seeds and nonzero
  exits; no failed game advances a team. Keep the existing meaningful historical
  reproductions as applicable. Private integration reports remain ignored.
- Add test-first synthetic/public-2026 cases for multiple season specifications,
  actual fixture selection, byes/membership/format differences, absent developer
  charts with valid generated charts, missing/contradictory historical data,
  illegal finals, missing rounds and independent historical-versus-simulated
  postseason identities. Unit tests load no historical/private season.
- Update affected guides and regression descriptions in the same behavior change;
  disclose changes to old generated-schedule test expectations. Run focused and
  required full regression at a stable candidate before any push.

## Strength and policy assessment

Measure whether source-supported chart strengths and weaknesses affect simulated
results. Test whether Hard AI responds to its own offense/defense and the relevant
opponent chart strengths in controlled contexts; preserve game-state tradeoffs,
coaching variation and existing anti-concentration requirements. Verify actual
data flow rather than assuming configured Hard means chart knowledge is used.

Separate fixed-policy chart comparisons from fixed-chart policy comparisons;
retain repeated-season uncertainty and inspect material inversions. Existing
DATA-018 and AI-025 findings remain separately tracked. Do not invent frequency
caps or change historical targets to make those diagnostics pass.
