## Description

Owner decision 2026-11-14: local pre-push should not pay for whole-package branch coverage. The 2026-11-14 full regression measured 11,315 core cases in 4,128.53s (1:08:48) with coverage at 86%, against 1,049s for the same complete suite without coverage in this session, and VAL-020 records 690.20s for a clean tracked-only no-coverage run. Coverage measured the whole package on every push, including code nobody changed, while CI already runs the full suite with coverage on Python 3.10 for every push. The requested policy is to measure coverage for the modules a fix touches while fixing, review the missing lines and branches, and let CI publish the authoritative full-coverage evidence for the pushed commit.

## Resolution / verification

- AGENTS.md documents targeted per-module coverage while fixing and keeps the pre-push core command complete but without coverage; CI full coverage remains the authoritative evidence for a pushed commit.
- paydirt/chart_release_gate.py keeps coverage in the strict candidate/charted-release inventory and drops it only for the released-charts pre-push route, so the one-command runner and the AGENTS checklist stay identical.
- Synthetic regressions cover both inventories, prove the pre-push core step still runs the whole tests/ suite, and require the AGENTS guidance text; no test, assertion or coverage exclusion is removed.

Implemented the owner decision. `AGENTS.md` now documents per-module coverage
while fixing (with `--cov=paydirt.<module>` examples for core and backend code,
the requirement to read missing lines/branches, and the rule to record or test
every intentional gap). The pre-push checklist core command keeps `-rs` and the
complete `tests/` path but no longer measures package coverage, and the section
explains that CI owns whole-package coverage for the pushed commit.
`required_regression_commands(released_charts=True)` matches that checklist, so
`scripts/run_full_regression.py` inherits the faster core step; the strict
candidate/charted-release inventory keeps `--cov=paydirt --cov-report=term`, so
`audit_regression_evidence` receipts are unchanged.

Baseline before the change: the two "keeps module coverage" controls passed, and
three new tests failed for the intended reasons (pre-push core still requested
coverage, and AGENTS.md had no targeted-coverage guidance). Added
`test_pre_push_core_route_runs_the_complete_suite_without_coverage`,
`test_strict_candidate_route_keeps_module_coverage`,
`test_agents_require_targeted_coverage_while_fixing` and the runner-level
`test_local_core_step_runs_the_whole_suite_without_coverage`, so dropping
coverage cannot quietly narrow the run or remove the candidate requirement.

Verification: 148 gate/runner/output/released/CI tests passed, then 226 with the
public-snapshot and OpenCode permission checks, plus 445 documentation and
tracker checks. Measured evidence for the policy is in VAL-020: 4,128.53s with
coverage versus 1,049s for the same complete suite without it.
