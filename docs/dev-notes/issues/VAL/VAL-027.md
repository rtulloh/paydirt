## Description

Owner decision 2026-11-14. The released-chart audit required every engine and backend module to match the immutable v1.10.3 tag byte for byte, and the v1.10.6 gameplay work (FLOW-023 end-zone interception decisions, FLOW-024 safety free-kick penalties, AI-002 defensive penalty choices) changed eight runtime modules. That made the required chart_1983 and chart_2024 steps fail for every v1.10.6 regression run, even though no chart, provenance, contract or metadata byte changed. The documented escape route was 'reviewed paired baseline regression evidence', which the audit explicitly does not implement, so no gameplay release could pass the gate. The owner wants chart integrity and engine validation separated: chart bytes and released public mechanics stay fail-closed, and engine changes are qualified by the full unit, gameplay, browser, historical-calendar and AI regression plus review.

## Resolution / verification

- The released audit fails on any chart, provenance, contract or metadata change (including the reviewed DATA-047 exceptions) and still runs released public mechanics whenever chart integrity holds.
- Engine and backend differences are reported in gameplay_identity (added/removed/modified files and inventory_changed) without failing the chart result; the legacy gameplay_implementation_unchanged field mirrors that observation.
- Version-only allowances cannot hide a behavior change: a non-version edit in paydirt/__init__.py or an API entry point still appears as a modified gameplay file.
- AGENTS.md and docs/released-chart-regression.md describe the separated contract, and the real 1983/2024 audits pass with their mechanics evidence present.
