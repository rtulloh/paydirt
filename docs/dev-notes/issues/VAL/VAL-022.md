## Description

The installed macOS arm64 v1.10.2 application exposes seasons but team-list requests fail with HTTP 500. The installed traceback identifies Pydantic's unresolved `Team` model and missing `Optional` namespace. Team files exist; this is not missing season data. The launcher executes the dynamically loaded routes module without first registering it in `sys.modules`, so postponed annotations cannot reliably resolve their owning namespace. Development-server checks import the module normally and miss this path.

## Resolution / verification

Register the actual routes module before execution, restoring the prior module on failure. Keep all API models in that correctly owned namespace rather than rebuilding individual models. Remove the unchecked duplicate/fallback team routes; the legacy season-path alias uses the same confined handler, and a backend import failure aborts startup explicitly.

A regression executes the actual launcher with PyInstaller's nested routes-file layout, a fresh module namespace and public 2026 teams. It fails first with the installed HTTP-500 behavior, then verifies team lists, every Pydantic model's completed schema, a new game and the confined legacy alias. All 23 focused launcher/path cases pass with one existing Starlette deprecation warning. Actual Codex review also verifies restoration for absent and pre-existing modules and finds no actionable defect. No existing test expectation was weakened.
