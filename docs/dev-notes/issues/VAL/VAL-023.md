## Target release

**1.10.4** — assigned to the release ticket fixer. Native Windows platform
reliability is release scope, not an optional post-release investigation.

## Description

Both Windows v1.10.3 published packages (installer and portable executable) pass
native version, team-list, rendered season grids, new-game and chart checks, but
the native smoke harness cannot confirm normal shutdown. Its isolated-console
Ctrl-C helper exits successfully; neither app emits the required shutdown marker
or exits within 15 seconds. The harness then forcibly cleans up the process tree.
Logs show no application traceback or API 500 during the functional checks.

This is an unresolved shutdown investigation, not a recurrence of VAL-022's
missing-team bug. Console-event delivery in the GitHub runner/harness may be
responsible; an application shutdown defect has not been established. Linux and
both Mac architectures pass normal shutdown in the same native workflow.

Evidence: [native published-asset run](https://github.com/rtulloh/paydirt/actions/runs/42538034057)
and [release validation](../../release-1.10.3-validation.md). Download identity,
logs and success/failure receipts remain in workflow artifacts and ignored local
`.ai-audits/release-readiness/v1.10.3/native-published/`.

## Resolution / verification

Determine whether the console event reaches the packaged Python child on a
native Windows runner. Compare a minimal console process and the published
portable/installed applications, accounting for PyInstaller parent/child console
handling. Distinguish a user closing the browser from stopping the app's server;
closing a browser alone is not proof of a shutdown defect.

If the harness is wrong, correct delivery test-first without relabeling forced
termination as normal shutdown. If the application is wrong, add synthetic/public
regressions before the production fix. Retain the actual published-asset functional
checks and negative controls for surviving servers, including HTTP error replies.

Before closure, verify both Windows package forms emit the normal shutdown marker,
release the listening port and leave no owned process tree, using the appropriate
normal shutdown mechanism. Inspect logs, retain exact artifact hashes and native
receipts, and disclose any remaining interactive console limitations. Run actual
Codex review on a fix before declaring it done. Do not require a new release if
only the verification harness needs correction.
