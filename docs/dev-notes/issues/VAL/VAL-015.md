## Description

In [run 41499019565](https://github.com/rtulloh/paydirt/actions/runs/41499019565)
the driver clicks a defense in Q1 at 6:56 immediately before the CPU's
fourth-down punt panel appears. That click does not execute a play. The driver
waits for an execution response instead of pressing EXECUTE PLAY, eventually
exhausting its six-minute two-game budget. This differs from the progressing
second-game timeout fixed and verified in VAL-014.

## Resolution / verification

Wait at most five seconds for either the action's response or its required
follow-up confirmation. Follow the CPU EXECUTE PLAY or normal-punt button
when it appears, then verify the actual execution response and game progress.
Retain all full-game assertions, original engine seeds, 450-action limits,
six-minute pair budget and zero retries.

Forward the first genuine CPU fourth-down response unchanged after an early
defense click. Require that the completed first game records the follow-up CPU
confirmation, so passing cannot silently avoid the race. This test-only delay
does not modify engine state, dice, clock or response content.

The forced handoff fails against the original driver in 17 seconds while the
offline-guide control passes. Fixing the driver exposes the application race
tracked in FLOW-012. Both actual full games and the guide must pass with that
application fix before closing.
