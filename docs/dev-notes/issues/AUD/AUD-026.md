## Description

A kickoff after a touchdown rolls a kicking-team foul. The generic CLI
penalty menu falsely previews a touchdown while describing the foul instead
of the potential retained kick and return. The CPU correctly chooses a
re-kick, and no spurious points enter the score.

`handle_penalty_decision` excludes field goals from its ordinary scrimmage
preview but applies `state.ball_position + play_result.yards >= 100` to
kickoffs. The stored prior scoring position plus penalty yards therefore
looks like another touchdown. The menu also says the down counts, which
is misleading for a kickoff decision.

## Resolution / verification

The engine supplies retained kickoff and re-kick previews from the actual
kick spot, distance and already-rolled return. Ordinary receiving spots,
touchbacks, out-of-bounds kicks and genuine touchdown cells have distinct
previews. Unresolved fumbles/return fouls are labeled as unresolved without
consuming additional dice or changing statistics. CLI displays these engine
previews and no longer treats penalty yards as a scrimmage gain or says that
a down counts on the kickoff decision.

Test-first baseline: ten expected failures and three existing passing CLI
controls. Focused kickoff/display checks pass. A 64-game public-chart audit
with a synthetic kickoff foul cell observes nineteen engine-owned previews.
Both complete browser games and offline-guide checks also pass.
