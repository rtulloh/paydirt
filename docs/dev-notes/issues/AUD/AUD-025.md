## Description

A live punt-return fumble showed the initial return yardage followed by the final scoring
position, creating an impossible movement narrative. The punt return's first segment and the
recovering team's subsequent fumble return are different movements. `_finish_punt_return_chain`
combined the first segment's `chain.yards` with the final `state.field_position_str()` after the
whole chain had been applied. Touchdowns are stored at position 99, so the sentence described
the initial return ending at the opponent's one rather than its actual fumble spot.

Compact CLI then unconditionally claimed the kicking team recovered every fumble and kept
possession, including when the receiver had actually recovered. Full CLI could label a kicking
team's fumble-return score as a punt-return touchdown. Both paths repeated touchdown announcements.

A synthetic public-team reproduction punts 44 yards from HOME 32: it lands at AWAY 24, a six-yard
return fumbles at AWAY 30, recovery roll 38 loses the ball to HOME, and HOME's 37-yard return cell
reaches the goal line. The touchdown, lost-fumble statistic, possession, and score are correct.
The presentation is wrong; neither the chart generator nor the scoring calculation causes it.

## Resolution / verification

Describe the initial return as occurring before a fumble, retain the engine's actual fumble/recovery
notes and dice trace, and then announce the final possessing team/spot or scoring team separately.
Avoid one-yard touchdown destinations. Populate the scoring-team result field in the engine.
CLI displays that narrative without inventing a recovery or a second touchdown label.

Keep open until committed. See the [investigation](../../punt-return-commentary.md). No regenerated
charts or changes to scoring, possession, recovery rules, dice consumption, or clock are needed.
