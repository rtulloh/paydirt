--- 2026-11-15 14:35 ---
Reproduced. Against the unchanged implementation, a public-2026 away-human game
mislabelled the possession team: with the away human on offense, the actual away
offense was shown as home; with the away human on defense, the human's own away
team was recorded as the offense instead of the home team that actually had the
ball. The corresponding home-human controls passed.

Play-log team labels now come from `possession` plus `humanIsHome` through a
shared `derivePlayLogTeams()` helper. `playerOffense` remains the correct flag
for which controls to show and which play key belongs to whom, but it no longer
selects the home/away team names. Entries written by this format also record the
human identity on every path (scrimmage, kickoff, PAT, CPU fourth-down kick,
penalty and end-zone interception).

--- 2026-11-15 14:52 ---
Code review found two follow-ups, now fixed. Penalty entries omitted
`humanIsHome`, so the renderer turned a correct home-human `playerTeam` into the
away team; every writer now records the human identity, and a four-case penalty
regression covers both human sides on offense and defense. Separately, older
saved entries stored post-play possession, so re-deriving their labels would
reverse interceptions, lost fumbles and turnovers on downs. The renderer now
re-derives identity only for entries that explicitly record
`possessionSemantics: 'preplay'`; legacy entries keep their recorded teams and
colors. A save/replay regression confirms legacy entries round-trip unchanged.

Evidence: 385 frontend tests passed with Node 25's built-in webstorage disabled
so jsdom owns `localStorage`; Vite production build passed; 461 documentation and
issue-tracker tests passed; `git diff --check` is clean. The real-engine browser
regression, `e2e/play-log-labels.spec.js`, passed 2/2 on isolated ports for an
away human on offense and defense, checking both labels and colors. No private
charts were used. Full regression is required before any push.

Allowlist note: the Playwright-focused prefix was promoted into
`opencode.json` and the Codex runtime rules, along with `npx test`/`npx vitest`
flag variants (including pinned `@version` forms). Project-permission tests cover
both the newly allowed forms and near-miss package names that must still ask.

--- 2026-11-15 15:05 ---
Play-test confirmed in the browser against the live dev servers (Vite 5173, Uvicorn
8000) with the real engine, public 2026 Ironclads/Thunderhawks, Hard CPU and one
snap per case. Headless Chromium drove the rendered controls; colors below are
computed styles, not class names.

- Away human on offense (possession away): header `HBI vs MCT`, `OFF:` green
  (rgb(74,222,128)), `DEF:` red (rgb(248,113,113)).
- Away human on defense (possession home): header `MCT vs HBI`, `OFF:` red,
  `DEF:` green.
- Home human on offense: `HBI vs MCT`, green offense / red defense.
- Home human on defense: `MCT vs HBI`, red offense / green defense.

Every entry recorded `possessionSemantics: "preplay"` with the matching
`offenseTeam`/`defenseTeam`/`playerTeam`. One run drew a penalty; the follow-up
entry kept the human's color. The human's side stayed green/red-independent of
which team had the ball, which is the fixed behavior. No private charts used.
Closing: the reported mislabelling no longer occurs in the browser.

The remaining changed log paths were exercised in the same live session:

- Kickoff after a halftime setup, away human: header `HBI vs MCT` (HBI kicking),
  `OFF: KO` green for the human kicker, `DEF: KR` red.
- CPU extra point, away human: header `MCT vs HBI` (MCT scoring), `OFF: XP` red,
  `DEF: -` green; the try is attributed to the scoring side before kickoff arms.
- Legacy saved game loaded into the UI: a pre-`humanIsHome` penalty entry and a
  post-play-possession interception entry both kept their recorded `MCT vs HBI`
  labels and colors, confirming older saves are not reinterpreted.
