## Description

Both CLI postgame summaries query the tracker with exemplar distances but
print those exemplars as exact situations. `get_tendency(3, 5)` aggregates
third-and-4 through third-and-6, `get_tendency(2, 7)` aggregates second-and-7+,
and first-down queries aggregate every first-down distance. The displayed
counts and recommendations can therefore be misread as evidence about an
exact distance. The supplied game has four third-and-4-6 pass calls but
only two exact third-and-5 calls; the summary labels all four as third-and-5.
This does not invalidate the overall run/pass totals or prove bad coaching.

Synthetic read-only probe: record two short-pass choices, on third-and-4
and third-and-6. `get_tendency(3, 5).total_plays` is two although there were
zero exact third-and-5 calls. The aggregation is intentional; the label is
the problem.

## Resolution / verification

Use accurate band labels (first down/any distance, second-and-7+, third-and-4-6)
or deliberately query exact-distance data if that is the desired report.
Do not silently change tracker bucketing or AI policy to fix a display label.
Cover new and resumed CLI summaries with synthetic/public fixtures. See the
[sanitized audit](../../game-audit-2026-10-28.md). No fix authorized.
