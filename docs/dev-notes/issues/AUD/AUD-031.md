## Description

The ignored return-exposure experiment keeps outcome and return-chain `id()` keys after their objects have been destroyed. Python can reuse those identities for later plays or games. A later completion then rewrites an earlier root's final snapshot; stale settlement or restore entries can also attach to another chain.

The same deterministic development schedule produced identical game receipts and selection totals in runs 07 and 08, but 2,343 final snapshots and one settlement differed. Those prior snapshots cannot prove historical final state. This is a local evidence-recording defect; no game-engine or chart mutation was observed.

## Resolution / verification

The separate run-09 observer keeps strong references for the lifetime of both identity registries and checks object and game identity before confirming a root. The measurement checks registry key sets. Earlier receipts remain immutable. Closed for this local observer defect after independently reviewed actual 272-game accounting and snapshot evidence. Source/model eligibility and release acceptance remain held.
